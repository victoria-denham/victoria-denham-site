Part one — the feedback system

Data nobody could use.

NDC ran training workshops and support groups constantly — and collected participant feedback at the end of every single one. Over time, this had accumulated into roughly 20–25 separate workbooks, each formatted differently, each sitting in isolation.

Nobody could see patterns across sessions. Nobody could pull quotes for reports or the website. The qualitative data — the actual written feedback, the things participants said — was completely inaccessible at any useful scale.

There was also a structural problem nobody had addressed: the questions asked at different sessions were worded slightly differently each time, making comparison across workbooks nearly impossible.

What was broken
  • ~20–25 separate feedback workbooks with no consolidation
  • Inconsistently worded questions across sessions — impossible to compare
  • Qualitative data (written feedback, quotes) completely buried
  • No way to search or filter across the full dataset
  • No publishing workflow — moving anything to the website was manual
What I built — part one

A searchable, publishable qualitative data system.

  • 01
    Consolidated master workbook Pulled all ~20–25 separate feedback workbooks into one master file. Cleaned and standardised the data, resolving inconsistencies in question wording and formatting across sessions.
  • 02
    Qualitative data publishing layer Built a dedicated layer focused on written feedback and quotes. Each entry could be marked positive, negative, or neutral, assigned to a specific page on the website or flagged as internal or stakeholder-only.
  • 03
    Keyword search and tagging system Added a keyword search pipeline that generated a dynamic column of matched tags — so anyone could search by topic and instantly surface all relevant quotes from across the entire dataset.
  • 04
    Strategic proposal on feedback improvement Wrote a formal proposal on how to fix the underlying data quality problem — recommending consistent question wording, better collection design, and a unified approach to qualitative feedback across all programmes.
Part two — the scraping project

"Do that manually."
I didn't.

Some time after the feedback system was complete, I was asked to go through the NDC website and manually copy every quote that appeared into a spreadsheet — then replace them with quotes from my workbook. The implication was that this would take the best part of a week.

"I understood the site well enough to know that every single quote on the website was wrapped in the same CSS class. So I didn't copy them manually. I scraped the whole site."

Every quote block, extracted automatically using Python, imported and Power Queried into a clean spreadsheet in around an hour. Then I built a publishing layer for the scraped quotes matching the structure of the feedback system — so replacements could be reviewed and approved properly, not just swapped in blindly.

The task had been designed as busywork. It ended up as a case study in why automation exists.

What I built — part two

Python scraper + approval layer.

  • 01
    Python web scraper Identified that all website quotes shared the same CSS wrapper. Wrote a Python script to scrape every instance from the site automatically — extracting clean quote text with no manual copying.
  • 02
    Power Query import and cleaning Imported the scraped data, cleaned and structured it using Power Query, and prepared it for comparison against the master feedback workbook.
  • 03
    Publishing approval layer Built a structured review sheet for managing the quote replacement process — so decisions about what to keep, replace, or remove could be made deliberately rather than haphazardly.

The result: data that actually works for you.

  • ~20–25 fragmented feedback workbooks consolidated into one searchable, publishable system
  • Qualitative data — the quotes, the written feedback — made accessible and usable for the first time
  • Keyword tagging means anyone can surface relevant quotes by topic in seconds
  • A week of manual quote-copying done in approximately one hour with Python
  • Strategic proposal submitted on how to fix the underlying data quality problem at source
